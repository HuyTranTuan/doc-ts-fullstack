Chặng 1: TypeScript (Cái móng nhà)

Hiểu sâu Type/Interface và Generics là điều kiện tiên quyết để code NextJS và NestJS không bị báo lỗi đỏ lòm. Mọi thứ quy chuẩn sẽ giúp bạn đỡ debug hàng giờ liền.

# 1. Type Alias vs Interface

Interface (Nên dùng cho Object/Class) Type Alias (Nên dùng cho logic/Union) 
interface User { id: number; }
// Kế thừa bằng "extends"
interface Admin extends User { role: string; }

// Gộp (Declaration Merging) - Tự động nối khi trùng tên
interface User { age: number; }

Thường dùng trong NestJS (DTOs, Repositories).

 
type User = { id: number; }
// Kế thừa bằng dấu "&" (Intersection)
type Admin = User & { role: string; }

// LỖI: Không thể khai báo đè tên Type đã có
type Status = 'success' | 'error';

Dùng nhiều trong React (Props, Union Types).

# 2. Generics (Biến Kiểu Dữ Liệu)

// T là "biến kiểu dữ liệu" sẽ được truyền vào khi gọi hàm
async function fetchData<T>(url: string): Promise<T> {
  const res = await fetch(url);
  return res.json();
}
// Truyền interface User vào hàm, TS sẽ hiểu biến user có thuộc tính name
const user = await fetchData<User>('/api/user');

# 3. Utility Types Thực chiến

Partial<T>

Biến TẤT CẢ thuộc tính thành Optional (?). Dùng khi update data.

Pick<T, Keys>

Giữ lại một vài thuộc tính chỉ định (vd: chỉ lấy name và avatar).

Omit<T, Keys>

Bỏ đi một vài thuộc tính (Ví dụ bỏ password ra khỏi User object).

Record<K, T>

Tạo Object có tập hợp các Key K và value đều thuộc kiểu T.

# 4. TypeScript Nâng Cao (Pro level)

// 1. typeof, keyof & as const
const COLORS = { red: '#f00', blue: '#00f' } as const; // as const ép kiểu thành Readonly, cấm sửa đổi.

// Trích xuất kiểu dữ liệu của biến COLORS đang có
type ColorObj = typeof COLORS;

// Lấy ra danh sách các Keys của Object đó -> "red" | "blue"
type ColorKeys = keyof ColorObj;
// 2. Lấy kiểu trả về (ReturnType & Awaited)
const getUser = async () => { return { id: 1, name: 'Bob' } };

// Lấy kiểu Promise<{id: number, name: string}>
type UserPromise = ReturnType<typeof getUser>;

// Dùng Awaited để bóc lớp vỏ Promise ra, lấy kiểu lõi bên trong
type User = Awaited<UserPromise>; // {id: number, name: string}

Chặng 2: Next.js 14/15 (App Router)

Kiến trúc Server-first. Next.js giờ đây gom gọn cả Backend nhẹ vào Frontend. Phải rạch ròi tư duy giữa cái gì chạy trên Server (để SEO, giấu API Key, Caching) và cái gì chạy dưới Client (trình duyệt người dùng để tương tác).

# 5. Server vs Client Components

Server Component (Mặc định)
Không có useState, onClick. Chạy ngầm trên server, trả về HTML thuần. Hoàn hảo để: Fetch DB, SEO, giấu API Key.
export default async function Page() {
  const data = await db.query('...');
  return <div>{data.title}</div>;
}
Client Component ("use client")
Dùng khi cần tương tác (Click, Form) hoặc Hooks (State, Effect, DOM API). Mã JS sẽ bị tải xuống máy người dùng.
"use client";
import { useState } from 'react';
export default function Btn() {
  const [st, setSt] = useState(0);
}

# 6. Routing Chuyên Sâu (App Router)

// File System Routing: Thư mục tạo ra URL, các file đặc biệt đóng vai trò Render

app/
├── [id]/page.tsx -> Dynamic Route. VD: /post/123 (Nhận params.id)
├── [...slug]/page.tsx -> Catch-all Route. VD: /shop/clothes/tops (Bắt mọi sub-path thành array)
├── (auth)/login/page.tsx -> Route Group. Ngoặc đơn tàng hình, URL vẫn là /login (Giúp gom nhóm layout)
├── @modal/(..)photo/ -> Intercepting + Parallel: Hiện Photo dưới dạng Modal đè lên trang hiện tại thay vì chuyển trang. (Hơi khó hiểu, giống feed Instagram).
└── api/users/route.ts -> Route Handler: Viết REST API (GET, POST...) giống Express (Thay thế API Routes cũ).

5 File Đặc biệt cốt lõi

  • layout.tsx: Khung bọc ngoài (Navbar/Footer). Không bị render lại khi đổi trang.
  • page.tsx: Giao diện chính của đường dẫn đó.
  • loading.tsx: Hiện Skeleton lúc fetch data (tự động bọc Suspense bên ngoài page).
  • error.tsx: Cần `"use client"`. Bắt lỗi crash UI cục bộ, không sập cả web.
  • not-found.tsx: Giao diện lỗi 404 tùy chỉnh.

# 7. Caching (Sức mạnh 4 tầng của Next.js)

Next.js mặc định cache cực kỳ gắt gao để tối ưu tốc độ. Có 4 tầng cache (Next 14+) bạn bắt buộc phải phân biệt được:

1. Request Memoization

Vị trí: RAM Server. Nếu bạn gọi fetch('api/user') ở Layout, rồi gọi Y HỆT lệnh đó ở Page trong cùng 1 vòng đời render. Nextjs chỉ gọi mạng 1 lần, lần 2 lấy từ RAM ra xài (Deduplication). Không cần truyền props lằng nhằng nữa.

2. Data Cache

Vị trí: Đĩa cứng Server. Kết quả của hàm fetch() được lưu lại vĩnh viễn trên ổ cứng (như Redis).
👉 Xoá/Cập nhật cache: Dùng revalidatePath('/blog') hoặc revalidateTag('tag1') trong Server Action, hoặc next: { revalidate: 3600 } (Tự xóa sau 1h - ISR).

3. Full Route Cache

Vị trí: Đĩa cứng Server. Lúc build (npm run build), Next render sẵn ra HTML tĩnh cho các trang không có biến số động (Static generation). Để ép 1 trang luôn render động mỗi khi có request: export const dynamic = 'force-dynamic';

4. Router Cache

Vị trí: Trình duyệt Client. Khi người dùng chuyển trang tới lui (bằng <Link>), Next giữ lại kết quả (RSC payload) của các trang đã đi qua trong vài giây để bấm `Back` không phải tải lại báo. Xóa bằng: router.refresh().

Top 3 Custom Hooks "Quốc Dân" bạn nên có

1. useDebounce (Chống Spam Gọi API khi gõ ô Search)
export function useDebounce<T>(value: T, delay: number): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(timer); // Clear ngắt nhịp nếu người dùng gõ tiếp
  }, [value, delay]);
  return debouncedValue;
}
2. useLocalStorage

Bọc useState lại, tự động JSON.stringify và đẩy xuống LocalStorage để giữ State khi load lại trang (Lưu ý cẩn thận lỗi Hydration SSR).

3. useOnClickOutside

Bắt sự kiện mousedown trên document. Nếu click chuột không rơi vào cái ref của Component thì thực thi hàm đóng Modal/Dropdown.

# 9. Kỹ Thuật Next.js "Pro" (Tuyệt chiêu)

🛡️ Protected Routes bằng middleware.ts

Chặn ở vòng gửi xe (Edge Network). File này phải nằm ở thư mục GỐC (ngang hàng src/). Nó chạy trước khi request tới trang để kiểm tra Token JWT.

import { NextResponse } from 'next/server';
export function middleware(req: Request) {
  const token = req.cookies.get('token');
  if (!token && req.nextUrl.pathname.startsWith('/admin')) {
    return NextResponse.redirect(new URL('/login', req.url)); // Đá ra trang login
  }
}
export const config = { matcher: ['/admin/:path*'] }; // Chỉ chạy middleware với route này

# 11. Kiến trúc Module, Controller, Provider

// 1. SERVICE (Provider / Đầu bếp - Nơi xử lý Logic / Gọi DB)
@Injectable() // Dán nhãn này thì nó mới có thể bị "bơm" (Inject) vào nơi khác
export class UsersService {
  findUsers() { return [{ name: 'Alice' }]; }
}

// 2. CONTROLLER (Lễ tân - Nơi định nghĩa Route, nhận Request)
@Controller('users')
export class UsersController {
  // (Dependency Injection): Giao Đầu bếp cho Lễ tân sử dụng
  constructor(private readonly usersService: UsersService) {}

  @Get()
  getUsers() { return this.usersService.findUsers(); }
}

// 3. MODULE (Phòng ban - Đóng gói Lễ tân và Đầu bếp lại 1 cục)
@Module({
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService] // Xuất ra ngoài để Module khác (như AuthModule) gọi ké Service này
})
export class UsersModule {}

# 12. Request Pipeline & Format Data JSON

Thứ tự luồng Request đi trong NestJS: Middleware → Guard → Interceptor (Pre) → Pipe → Controller → Interceptor (Post) → Exception Filter.

1. AuthGuard (Bảo vệ Route / Check JWT)

Thay thế auth middleware. Trả về true thì cho qua, false ném lỗi 403 Forbidden.

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest();
    const token = req.headers.authorization;
    if (!token) return false;
    return true; // Cho qua (hoặc check jwt.verify)
  }
}
// Dùng trên Controller: @UseGuards(AuthGuard)

2. Middleware (Kế thừa Express)

Dùng tham số (req, res, next) y hệt Express. Chuyên dùng để logging, chặn IP.

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    console.log(`Request... ${req.method}`);
    next(); // Quên gọi next() là treo server
  }
}
// Đăng ký trong AppModule (implements NestModule)
3. Interceptor (Tự động bọc Data vào { statusCode, data, message }) Copy 
// Khắc phục tính dài dòng của Express. Controller của bạn giờ chỉ cần "return {name: 'A'}"
// Interceptor này sẽ bắt lại và bọc nó thành: { statusCode: 200, message: 'Thành công', data: {name: 'A'} }
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { map } from 'rxjs/operators';

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      map(data => ({
        statusCode: context.switchToHttp().getResponse().statusCode,
        message: 'Request thành công',
        data: data || null,
      })),
    );
  }
}
// Kích hoạt toàn cục trong main.ts: app.useGlobalInterceptors(new TransformInterceptor());

# 13. Kỹ thuật Đỉnh cao (Decorators & Injection Scopes)

Tạo Custom Decorator (@CurrentUser)

Sau khi Guard check Token xong, nhét User vào `req.user`. Lúc này ta tạo Decorator để lấy nó ra ở Controller cho gọn (Thay vì gọi `req.user` lặp đi lặp lại).

import { createParamDecorator, ExecutionContext } from '@nestjs/common';

export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.user;
  },
);

// Cách xài: @Get() getProfile(@CurrentUser() user: UserEntity) {...}

Injection Scopes (Vòng đời của Provider)

Mặc định Service trong NestJS là Singleton (Chỉ khởi tạo 1 lần dùng chung cho mọi user). Nếu muốn mỗi Request là 1 bản copy riêng thì xài Scope.

  • Scope.DEFAULT: (Khuyên dùng) Singleton. Tiết kiệm RAM.
  • Scope.REQUEST: Tạo class Service MỚI HOÀN TOÀN với mỗi Request gửi lên. (Ngốn RAM, cân nhắc khi làm Multi-tenant DB).
  • Scope.TRANSIENT: Khởi tạo mới mỗi khi bị Inject vào nơi khác.

Chặng 4: Từ Điển Thuật Ngữ IT

Gặp mấy từ viết tắt hay tiếng Anh này thì cứ mở bảng này ra xem. Giải thích cực ngắn theo ngôn ngữ con người (không văn vở học thuật).

🌐 SSR (Server-Side Rendering)

Trình duyệt xin trang web, Server (Next.js) lấy data, lắp ghép sẵn ra HTML 100% hoàn chỉnh rồi mới trả về trình duyệt. Rất tốt cho SEO (Google bot đọc được ngay).

💻 CSR (Client-Side Rendering)

Kiểu cũ của React/Angular. Server trả về file HTML trống trơn + cục JS khổng lồ. Trình duyệt nhận về, hì hục chạy cục JS đó để vẽ lên giao diện. Bất lợi: Load lần đầu chậm, bot Google không đợi được để đọc.

⚡ SSG & ISR

SSG: Build sẵn ra cục HTML vĩnh viễn lúc gõ `npm run build`.
ISR: Giống SSG nhưng có tính năng "Hẹn giờ". VD hẹn 60s thì cứ sau 1 phút, nó ngầm build lại cục HTML tĩnh mới nhất thay cho cục cũ.

💧 Hydration (Bù nước)

Cục HTML từ SSR trả về chỉ là "xác khô" (xem được nhưng không click được). Quá trình đính kèm các cục JS sự kiện (onClick, State) vào HTML để nó "sống lại" và tương tác được, gọi là Hydration.

📦 DTO (Data Transfer Object)

Cái hộp chứa dữ liệu. Dùng để định nghĩa hình dáng cục data gửi từ Frontend lên Backend (VD: CreateUserDto gồm email, password), giúp check xem FE gửi lên có thiếu trường nào không.

🗄️ ORM (Prisma / TypeORM)

Phần mềm trung gian phiên dịch code TypeScript (OOP) sang câu lệnh truy vấn SQL thô. Giúp bạn code Database bằng Javascript mà không cần nhớ cú pháp SQL.

💉 DI & IoC (Dependency Injection)

Thay vì class A tự dùng lệnh `new ClassB()` (tự mua nguyên liệu nấu ăn), thì Framework (NestJS) sẽ tạo sẵn ClassB bên ngoài và "bơm" (Inject) vào Class A qua Constructor. Làm vậy để lúc Test có thể nhét đồ giả (Mock) vào dễ dàng.

🔑 JWT (JSON Web Token)

Thẻ ra vào dạng chuỗi mã hóa. Đăng nhập đúng, Backend cấp 1 thẻ Token. Lần sau FE muốn làm gì thì kẹp thẻ Token này vào Header (Bearer token) gửi lên. (Gồm Header, Payload, Signature).

🚫 CORS (Cross-Origin)

Lỗi bảo mật nổi tiếng nhất. Trình duyệt mặc định CẤM Frontend ở tên miền a.com gọi sang Backend ở tên miền api.b.com để chống trộm data. Backend phải bật cấu hình cho phép tên miền a.com đi vào thì mới hết lỗi đỏ.
